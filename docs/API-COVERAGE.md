# API coverage: what the C differential actually judges

Generated by `tools/api-census` -- **do not edit by hand**; `census.py --check` fails if this file disagrees with `docs/api-coverage.json`.

**Method.** LLVM source-based coverage (`-C instrument-coverage`, rustc 1.98.0) over five groups of runs, each attributed by source line to the innermost function holding it -- so inlining and generics do not hide anything. A *region* is one straight-line piece of code; a function's regions are its arms.

| group | what runs | compared to the C? |
|---|---|---|
| **C1** | `rusty_rtos_demo` `conformance`: all 25 pins -- the 24 scenarios plus `PollQ-typed` (2,000 ticks; `death` 4,000) -- and the async arm, each against the C kernel's own trace digest and counters | yes, one core |
| **C1L** | `kairos-sim` at full length (100,000 ticks) on the 26 scenarios `kairos conform` reported identical to the LIVE C kernel in the same session, 18,403,837 trace lines in all | yes, one core |
| **C2** | `smp_conformance` (nine scenarios, 20,000 ticks) + `smp_differential` (two 20,000-step scripts) | yes, two cores |
| **EQ** | `typed_equivalence`: every typed wrapper on a real kernel, its calls recorded at the `Raw` boundary and replayed directly on a twin kernel (plan P4) | no -- each wrapper proved to make exactly the C-twinned calls C1/C2 compare; credited to `typed.rs` only |
| **ANY** | every test in the kernel and the demo, both feature sets | no -- *executed*, not *compared* |

**What a covered region does and does not prove.** A region C1 or C2 executed ran inside a run whose trace, exits and counters matched the C's -- so what it decided was compared. It is not yet proof that a WRONG decision there would have been caught; that needs a poison per API (the plan's P1). The **one core** column is C1 or C1L: the pins are what CI can re-check without a C toolchain, and the full-length runs are what they miss -- TimerDemo's Test6, for one, starts after 2,000 ticks.

## Arms judged by a written reason

Each reason is an entry in `tools/api-census/reasons.json`, keyed by function and the text its arm begins with; the census refuses a reason that no longer matches an unjudged arm, so a reason cannot outlive its code.

| class | what it means | entries | functions |
|---|---|---:|---|
| between-lists | a live task on no list, which exists only inside a call, between a removal and an insert -- no caller can ask then. | 3 | `state_of`, `task_delete` |
| c-undefined | the C configASSERTs, so the call is undefined there; Kairos refuses it instead. No C answer exists to compare with (D1's reasoning, for a refusal that is not spelled Err). | 4 | `timer_command`, `timer_command_from_isr` |
| config | an arm compiled for a configuration neither compared build uses (configUSE_PREEMPTION 0). | 1 | `set_priority` |
| debug-only | an argument of a debug_assert: release builds never evaluate it, and every compared run is a release build. | 1 | `increment_tick` |
| defensive | the else of a lookup the same call has already proved -- a handle resolved or checked live above, an index validated at entry, the running task's own TCB, a slot the face wrote two lines up. The C indexes directly and has no such branch, so there is nothing to compare. | 28 | `abort_delay`, `create_task`, `enter_critical`, `event_group_set_bits`, `event_group_sync`, `event_group_wait_bits`, `notify_state_clear`, `notify_take`, `notify_wait`, `semaphore_create_counting`, `send`, `send_from_isr`, `suspend` |
| exhaustion | the TCB arena is full. Kairos's arena is a compile-time size; the C (heap_3) fails a create only when malloc does, which no comparable run makes happen. The trace event is the C's own traceTASK_CREATE_FAILED. Unit-tested. | 3 | `create_task` |
| integrity | the scheduler's stall diagnostics -- a ready list above the configured ceiling, no ready task, a state item that names no task. The C has no conforming behaviour there (it indexes out of range or asserts); Kairos stops and names the stall. No ready task is unit-tested; the other two need a corrupted list, which the safe API cannot build. | 6 | `switch_context` |
| interrupt-window | a re-check, or a 'did resuming the scheduler already yield', that only an interrupt landing BETWEEN two reads inside one call can change. The API differential delivers interrupts between calls; the corpus's exit-clocked ticks never landed there in 26 scenarios x 100,000 ticks. | 6 | `delay_until`, `event_group_wait_bits`, `notify_take`, `notify_wait` |
| pre-scheduler | vTaskSuspend of the running task before the scheduler starts: every compared run starts the scheduler before its first step. | 2 | `suspend` |
| shadowed | the one-core own-task shortcut of the section-free spelling: the compared spelling (task_state_get) answers it first; only a direct caller of state_of reaches it, and there the answer is the same Running. | 1 | `state_of` |
| storage | two cores: Kairos keeps the C's termination list as two reap slots; the second fills only when two deletions of running tasks land before the idle task reaps. | yield-window | two cores: a core asked to yield that has not yet taken it -- the C's taskTASK_SCHEDULED_TO_YIELD.
